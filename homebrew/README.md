# Homebrew tap for JTalk GUI

`Casks/jtalk-gui.rb` is generated by `npm run cask` from the artifacts in
`release/` and is not tracked here: its checksums belong to one specific
release, so the authoritative copy lives in the tap repository. To publish it:

1. Create a repository named **`homebrew-jtalk-gui`** on the same account that
   hosts this project. The `homebrew-` prefix is what makes it a tap.
2. Copy `Casks/jtalk-gui.rb` into it, keeping the `Casks/` directory.
3. Push, then install with:

```
brew tap renorari/jtalk-gui
brew trust --cask renorari/jtalk-gui/jtalk-gui
brew install --cask jtalk-gui
```

`brew trust` is required from Homebrew 6.0 onwards: casks in taps outside the
official ones are not loaded until they are trusted explicitly, and refusing to
load is the default. Trusted entries are recorded in `~/.homebrew/trust.json`.
Trusting the tap as a whole (`brew trust renorari/jtalk-gui`) also works, but
naming the single cask keeps the grant narrower.

The cask declares `depends_on formula: "open-jtalk"`, so Homebrew installs the
engine, its dictionary and the bundled voices before the app.

## Releasing a new version

```
npm version patch          # or minor / major
npm run dist:mac           # builds release/jtalk-gui-<version>-{arm64,x64}.zip
npm run cask               # regenerates the cask with fresh checksums
```

Upload both zips to a GitHub release tagged `v<version>`, then commit the
regenerated cask to the tap.

## Gatekeeper

Homebrew always quarantines what a cask downloads. macOS refuses to open a
quarantined app that is not notarized, so without notarization users see
"cannot be opened because the developer cannot be verified" and have to clear
the attribute by hand:

```
xattr -dr com.apple.quarantine "/Applications/JTalk GUI.app"
```

To avoid that, sign with a **Developer ID Application** certificate (Apple
Developer Program, paid) and notarize:

```
export APPLE_ID="you@example.com"
export APPLE_APP_SPECIFIC_PASSWORD="xxxx-xxxx-xxxx-xxxx"
export APPLE_TEAM_ID="XXXXXXXXXX"
npm run dist:mac:release
```

Note that an **Apple Development** certificate is not enough. It is meant for
local development and Gatekeeper rejects it on other machines. `npm run dist:mac`
deliberately sets `CSC_IDENTITY_AUTO_DISCOVERY=false` so such a certificate is
never picked up from the keychain by accident.

## Submitting to the official homebrew-cask

Two conditions have to be met first:

- The app must pass Homebrew's Gatekeeper checks, which means a Developer ID
  signature and notarization.
- The project needs demonstrable public interest. A brand new repository will
  not be accepted.

`homebrew/core` is not an option: it does not accept formulae whose primary
output is a macOS `.app` bundle.
